# Деплой

Сайт собирается в статику: HTML, CSS, JS, картинки и шрифты. Node на сервере
не нужен, базы нет, формы уходят в WhatsApp. Подойдёт и обычный хостинг,
и VPS.

Сборка всегда делается локально — на сервер попадают только готовые файлы.

```bash
npm run build     # результат в out/
```

---

## Вариант 1. Обычный хостинг с панелью (рекомендуется)

Подходит любой тариф с поддержкой статики — cPanel, ISPmanager, DirectAdmin.
PHP, базы и Node не требуются.

1. Соберите проект: `npm run build`.

2. Залейте **содержимое** папки `out/` в корень сайта (`public_html`,
   `www` или `httpdocs` — зависит от панели).

   > Заливать нужно именно содержимое, а не саму папку `out`. Если на сервере
   > окажется `public_html/out/`, все пути вида `/_next/…` и `/images/…`
   > сломаются, и сайт откроется без стилей и картинок.

   > Файл `.htaccess` лежит в `public/` и попадает в `out/` при сборке —
   > заливать его отдельно не нужно. Но имя начинается с точки, поэтому
   > FTP-клиенты и файловые менеджеры часто скрывают такие файлы: убедитесь,
   > что он действительно выгрузился. В FileZilla: «Сервер» → «Принудительно
   > отображать скрытые файлы».

3. Выпустите SSL-сертификат в панели (обычно Let's Encrypt, бесплатно).

4. Блок принудительного HTTPS в `.htaccess` трогать не нужно: Plesk
   редиректит HTTP на HTTPS сам, на уровне nginx. Он оставлен
   закомментированным на случай переезда на хостинг без такого редиректа.

### Обновление сайта

Пересобрать и перезалить содержимое `out/`. `.htaccess` обновится вместе
с остальными файлами.

### Если сайт открылся с ошибкой 500

Почти всегда причина — строка `Options -Indexes` в `.htaccess`: часть
хостингов запрещает менять `Options` из пользовательских конфигов.
Удалите эту строку, остальное на работу сайта не влияет.

## Вариант 2. VPS с nginx

Конфиг: [`nginx.conf`](nginx.conf) — там же команды установки в комментариях.

```bash
npm run build
rsync -az --delete out/ user@server:/var/www/weldingcompany/
```

## Проверка после заливки

```bash
curl -I https://weldingcompany.kz/              # 302 на /ru/
curl -I https://weldingcompany.kz/ru/services/  # 200
curl -I https://weldingcompany.kz/kk/contacts/  # 200
curl -I https://weldingcompany.kz/net-takoy-stranicy/   # 404 со своей страницей
```

В браузере: открываются обе локали, на месте логотип и фотографии,
переключатель языка со страницы `/ru/projects/` ведёт на `/kk/projects/`,
кнопки WhatsApp открывают чат с заполненным текстом.

---

## Если хостинг на nginx и `.htaccess` не поддерживается

Корень сайта всё равно заработает: в сборке есть `index.html`, который
перенаправляет на `/ru/` без участия сервера.

За страницей 404, сжатием и кэш-заголовками придётся обратиться в
техподдержку — нужные правила можно передать им прямо из
[`nginx.conf`](nginx.conf).
